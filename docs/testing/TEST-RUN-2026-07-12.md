## 4. Findings register

### F-1 — Comic publish: spec↔handler drift (Severity **S3 Minor**, CC-7)

- **Spec (SPEC-02 §7):** publish/unpublish is a `PATCH /comics/{id}` with a `{status}` change.
- **Actual:** dedicated `POST /comics/{id}/publish` + `POST /comics/{id}/unpublish` endpoints.
  `PATCH {status}` **silently ignores** the `status` field → returns 200 with the comic still
  `draft` (also accepts a bogus status value with 200).
- **Feature is functional:** `POST /comics/{id}/publish` on an empty comic correctly returns
  **422** `{"type":"comic/not-publishable","detail":"every chapter must have at least one page"}`.
  Root cause: `svc.Publish` (service.go:124) validates correctly; only the route differs from the spec.
- **Impact:** a client following the OpenAPI contract cannot publish and gets a misleading 200.
- **Recommendation:** reconcile — either wire `PATCH {status}` to `Publish/Unpublish`, or update
  `shared/openapi.yaml` + SPEC-02 §7 to document the `/publish` + `/unpublish` endpoints. Minimally,
  PATCH should reject an unknown/ignored `status` (422/400) instead of silently succeeding.
- **Cases:** TC-COMIC-032/033/034/035 (contract path) vs the real endpoint (PASS).

### F-2 — Bank fractional amount → 400 not 422 (Severity **S4 Trivial**)

- **Spec (SPEC-03 P0.2):** a fractional VND amount → 422 `bank/invalid-amount`.
- **Actual:** `amount: 100.5` → **400** (JSON decode failure — `amount` is typed `int64`, a
  fractional literal never reaches validation). The amount **is** correctly rejected; only the
  status/Problem differs. `amount ≤ 0` correctly returns **422 `bank/invalid-amount`** (TC-BANK-025 PASS).
- **Impact:** cosmetic — invalid input rejected either way; no money-math risk.
- **Recommendation:** optionally decode `amount` as a number then validate integrality to emit
  the documented 422, or accept the 400 and note it in the spec.

### Observations (not defects)

- **No `GET /bank/accounts/{id}`** single-fetch endpoint (SPEC-03 §7 lists only list + PATCH/DELETE);
  `{id}` path returns 405 for GET. Isolation still enforced via PATCH/DELETE (404). Working as specced.
- **Budget `PUT /bank/budgets`** returns **204** (spec implied 200). Both are valid for an upsert;
  cosmetic.

## 5. Environment issue fixed during the run

Per plan §4 the `owner` handle must be `creator`-or-higher. The dogfood account
(`dogfood@portal.localhost`) was role **`user`** only, so `comics:write:own` was correctly
403'd — RBAC working as designed, but it blocked the comic P0 cases. Resolved by granting the
`creator` role + bumping `token_version` (cache invalidation) and re-logging in; the comic block
then passed. **This is a test-data provisioning step, documented here for reproducibility, not a code defect.**
